    API reference¶

    Lumped-element detectors, cavity haloscopes and SRF heterodyne cavities search for axion dark matter. Here we list the public objects of the axionmultiphysics Python package, grouped by topic.

    Errors¶

    Every error the package raises is an AxionMultiPhysicsError. Besides its text it has four attributes: where (a JSON pointer into the document, or an empty string), hint (what to change), code (a stable dotted identifier, or an empty string) and details (a dict of structured facts, or None; None also when the details are nested deeper than 64 levels, the details object being level 1, as on the command line and in the MCP reply). The command line prints code and details in its error JSON only when they are not empty (see the command line), and the MCP server's failure reply carries the same four fields.

    The physics catalogue (beta)¶

    axionmultiphysics.physics(routes=False, type=None) returns the physics catalogue of model documents as a dict, the JSON that axmp physics --json prints (schema axionmultiphysics.physics_catalogue/1): the physics types with their options, condition kinds, sources and quantities, the coupling terms, the reserved instance ids and, with routes=True, the route table and the layer rules. Everything in it is beta, and no route is implemented in this version. The reference page is generated from it.

    The codes that the findings about a model document carry are listed in the error codes of the model document, a page generated from the table of codes in the core (axionmultiphysics._core.error_codes() returns it as JSON text). Design.validate(strict=False, all_errors=False) of a model document (one with a top-level physics key) returns its validation report (ok, name, parameters, errors, unavailable, deferred, warnings), raising the first error (with strict, also the first unavailable finding) unless all_errors; axmp.load refuses a model document whose file repeats a key (json.duplicate_key). Design.boundaries(mesh=False, all_errors=False) returns the table of the named boundaries of a model document as axmp boundaries --json prints it (the validation report with symmetry, boundaries and edges added; mesh=True adds faces), raising the first error unless all_errors; axmp.mesh(d, workdir=None, mesher=None) meshes a model document (a Design or a dict) and returns a MeshedModel with symmetry, geometry_order, regions, boundaries, mesh_file, info_file and instance(domain=None), which returns the InstanceMesh of a region or domain name, a list of names or every region: its attributes, remaining_attributes, axis_attributes, master_attribute, region_attribute, the arrays vertices(), elements(), element_attributes(), boundary() and boundary_attributes(), section(name) and face_points(name=None, *, order, attribute=None), the quadrature on the faces of a boundary, a section or one instance attribute (the way to the edges no boundary names and to the axis), with the points, weights and normals as NumPy arrays. Both need the mesher: without one that runs they raise build.requires_mesher; a 3D document, a document on an imported mesh and (for axmp.mesh) a document with no geometry raise route.not_implemented; a failed mesher run is mesh.generation_failed; misuse of an instance mesh (an unknown name, an attribute that is not on it) is a ValueError; an electromagnetic design is refused without a code. An InstanceMesh also has fluids_mesh() (a fluids.Mesh copy of it; MPI builds, else build.requires_fluids) and chem_mesh(order=2) (a chem.TriMesh; MeshedModel.fluids_mesh(domain=None) and MeshedModel.chem_mesh(domain=None, order=2) are shorthands). See meshes of model documents. Design.solve refuses a model document with route.not_implemented, and the electromagnetic-only operations (Design.gradient, Design.optimize, axmp.optimize, axmp.global_optimize, sensitivity.optimize, convert.to_3d, comsol.export_comsol, the model classes of _core) refuse it with model.em_only_operation; both name the operation in details.operation. Design.explain() and Design.patch() read a model document too.

    Design.explain(json=False) returns the resolved model of a model document as the text that axmp explain prints, or with json=True as the dict of schema axionmultiphysics.explain/1. It raises AxionMultiPhysicsError for a document that fails validation (the first error) and for an electromagnetic design.

    Design.patch(ops) applies an RFC 6902 JSON Patch (a list of operations; paths are RFC 6901 JSON pointers) atomically and returns the design: either every operation applies and the result validates, or AxionMultiPhysicsError is raised and design.doc is unchanged. The keys of the patched document are in sorted order (the order of the keys of a JSON object carries no meaning). An operation that cannot be applied raises with the code patch.operation_failed and where /<index>; a result that does not validate raises the validation's own error. It works on electromagnetic designs too.

    physics ¶

    physics(
    routes: bool = False, type: str | None = None
) -> dict

    The physics catalogue of model documents (beta), as axmp physics --json prints it.

    The catalogue lists the physics types (their options, condition kinds, sources, quantities per geometry class and what is not implemented), the coupling terms and the reserved instance ids; routes=True adds the route table, one row per combination of physics, couplings, geometry class and study type that an engine of this version solves, with what each row offers and needs, and the rules of this layer. Every entry is beta, and no route is implemented yet (every row has "implemented": False and "status": "not_implemented"). The catalogue is the same in every build. The schema string is axionmultiphysics.physics_catalogue/1.

    Parameters:

    Name Type Description Default
    routes bool

    Add the route table ("routes") and the layer rules ("layer_rules").

    		 False
    type str | None

    Restrict the catalogue to one physics type, the rows whose physics contain it and the coupling terms it produces or consumes.

    		 None

    Returns:

    Type Description
    dict

    The catalogue: schema, status, types, terms, reserved_ids and, with routes=True, routes and layer_rules.

    Raises:

    Type Description
    AxionMultiPhysicsError

    type is not the name of a physics type (an alias is refused too); the hint names the types.

    validate ¶

    validate(
    strict: bool = False, all_errors: bool = False
) -> dict

    Parse and check the design in C++; raises AxionMultiPhysicsError with a hint on problems.

    A model document (one with "physics") returns the validation report: ok, name, parameters and the findings errors, unavailable, deferred, warnings. It raises the first error, and with strict the first unavailable finding; all_errors=True returns the report without raising. An electromagnetic design ignores both flags.

    boundaries ¶

    boundaries(
    mesh: bool = False, all_errors: bool = False
) -> dict

    The named boundaries of a model document, as axmp boundaries --json prints them (beta).

    Validates the document, runs the mesher's resolve_only pass and the full check (the partition rule of every physics, the empty selections, the partial matches, the outputs on resolved boundaries), and returns the validation report with symmetry, boundaries (one row per name: selector, entities, measure, bbox, point, adjacent, used_by) and edges added. mesh=True also meshes the model and adds the number of boundary elements, faces, to every row and edge. Raises AxionMultiPhysicsError with the first error (also build.requires_mesher when the mesher does not run, and mesh.generation_failed); all_errors=True returns the report instead of raising. Needs the mesher; an electromagnetic design is refused.

    explain ¶

    explain(json: bool = False) -> 'str | dict'

    Global minimization (or maximization) of a figure of merit by differential evolution.

    params (or its alias bounds; not both) maps parameter names to (low, high) or (low, high, "log"); log lists parameters searched in log space (use it for sizes and ratios spanning decades). objective is a quantity name (axionmultiphysics.objectives(), e.g. "cost", "cost_optimal:conservative", "g_factor") or a picklable callable f(results) -> float (importable by name in a worker when workers > 1 or a map is given). constraints holds {"quantity": "sc_surface_at_req", "type": "<=", "value": 0.093} entries (or 3-tuples); they are enforced by the feasibility rule, not by a penalty weight. values are keyed by the quantity name; a callable by its __name__ ("custom" without one), suffixed #2, #3 ... when that key is already taken (two lambdas, or a callable named like a quantity). A feasible objective must have |f| < 1e99 (larger values are failed points: rescale).

    DE settings are scipy's: the population has max(5, popsize * len(params)) members (rounded up to a power of 2 for init="sobol"; an init array is given in parameter units, one row per member, inside the bounds), at most maxiter generations after the initial one. The search stops when the whole population is feasible and std(f) <= atol + tol * |mean(f)| (scipy >= 1.12; older scipy runs all maxiter generations). It is deterministic for a given seed: every evaluation (serial, pool or map) and the polish run on threads OpenMP threads (default 1; the calling process is set to it and restored on return), so that the solver's parallel sums do not depend on the thread count. workers > 1 evaluates each generation on a process pool (-1: the CPUs this process may use, divided by threads); a callable workers(fn, tasks) -> records (a map) distributes evaluations elsewhere, e.g. a SLURM array. Scripts that use a process pool must guard their entry point with if __name__ == "__main__":.

    Failure handling. A shape that fails to mesh or solve is an infeasible point. With a process pool (workers > 1) also: an evaluation slower than timeout [s] (killed when still running timeout s after submission, which includes a worker's start-up after a restart, then the pool is restarted and the other running points are re-run; a finished one whose own run time exceeds timeout is charged too) and a worker that dies (the points running with it are re-run one at a time, so the crash is charged to the point that caused it). In serial mode (workers=1) timeout is ignored (with a warning) and a hard crash of the solver ends the run. Nothing is saved before the run returns. An error of the configuration (an unknown benchmark, cost_optimal on an iron design, a nonlinear design without an amplitude parameter, NI optimized while it is the amplitude, a callable that cannot be loaded in a worker, ...) is raised as ValueError at the first evaluation that shows it, instead of failing every point.

    max_time [s] is checked after every generation (not inside one, nor during the initial population): the search then stops, the polish is skipped if the time is exhausted, the Powell polish stops when it is, and the adjoint polish (which cannot be interrupted; at most polish_max_iter iterations) is replaced by Powell unless 7 (polish_max_iter + 1) evaluations of the DE's mean duration fit in the remaining time (an iteration takes several solves). max_time is thus a soft bound: the last generation, a Powell evaluation, or an adjoint polish that needs more solves than this estimate can overrun it. callback(generation, best_record) returning True stops the search too.

    precheck(parameters) rejects a point before it is meshed: a returned string (the reason, also an empty one), False (also numpy.False_) or a raised exception rejects it, None or True (also numpy.True_) accepts it; any other return value is an error. Use it for cheap geometric rules (wall thickness, corner radii). polish="adjoint" cannot apply it and is refused with a precheck.

    Requirement quantities (cost, cost_optimal, W_at_req, sc_surface_at_req, ...) are read at F = F_req: by the solver's exact rescaling for linear designs, as by axionmultiphysics.optimize(); when the rescaling is not exact (nonlinear iron, or fixed sources such as a background field) the parameter amplitude (default "NI") is solved for F = F_req of the objective's benchmark to amplitude_tol (log-secant, at most amplitude_max_solves solves), and all requirement quantities must then refer to that benchmark. A nonlinear solve whose Newton iteration did not converge is a failed point. Known limitation: the amplitude at which the other quantities are read differs by case. When the root runs (a requirement quantity or any callable is asked for on a nonlinear design or one with fixed sources), every quantity and callable -- also B_peak, W_mag, sc_surface_peak -- is read at the root amplitude; on a linear design without fixed sources, non-requirement quantities and callables see the design's own NI. A constraint such as ("B_peak", "<=", 6) therefore means different things in the two cases; use the *_at_req quantities for limits at the operating point. A callable on a nonlinear design needs the amplitude parameter and costs the ~3 solves of the root.

    polish: True/"auto" refines the best point with the adjoint-gradient optimizer when the design is linear without fixed sources (no amplitude root), the objective and constraints are named quantities, no precheck is given and order is 0, else with bounded Powell; "adjoint" (falling back to Powell if the adjoint optimizer fails or the point needed the amplitude root), "powell" or False choose. The polished point replaces the DE point only if it is feasible and better.

    Returns the structure of axionmultiphysics.optimize() (parameters, values, caps, constraints, design, history of every evaluation with stage, generation, energy and feasible), plus feasible, de (generations, evaluations, convergence, scipy's own message), de_best, polish and found_by. converged is the DE convergence test above and message says how the search ended. evaluations is len(history) (DE and Powell points, adjoint iterates, precheck rejections); solves counts the FE solves (one per evaluated point, plus the amplitude-root and adjoint-polish solves). The default workdir is a new directory per run under runs/<design>__global/.

    equivalent ¶

    equivalent(
    omega0: float | None = None,
    f_Hz: float | None = None,
    dlog: float = 1e-05,
    corr_tol: float = 0.01,
) -> dict

    Reduce the network to the single-pole detector the optimal scan assumes.

    Definitions (all exact for the series topology):

    • omega0 : Im Z_eff(omega0) = 0
    • R_eff : Re Z_eff(omega0)
    • L_eff : |dIm Z_eff/domega|/2 at omega0 (the reactance-slope inductance; = L_p + L_in + L_lead for a series loop)
    • Q_loaded : omega0 L_eff/R_eff
    • n_eff : from sum_k |H_k/H_s|^2 R_k (2 n_k + 1) = R_eff (2 n_eff + 1), so the referred thermal noise is matched exactly; T_eff/Q = sum_k T_k/Q_k classically
    • xi : 2 R_eff S_Phi/(hbar omega0 |M_eff|^2)
    • participation: L_p/L_eff, the amplitude factor; the scan rate carries its square

    With a correlated SQUID (S_PhiJ != 0) the noise is reduced by completing the square; correlated_reduction_resid compares that pole with the exact N_V at the noise-doubling points and the call raises above corr_tol.

    react_resid, R_noise_over_R_eff, backaction_transfer_ratio and reciprocity_resid are the diagnostics that say how good the reduction is: the first should be ~0, the next two ~1, the last ~0. R_noise_over_R_eff is the Nyquist identity referred with the pickup current (the flux referral is not an identity); reciprocity_resid is the asymmetry of the solved branch transfer matrix, and matrix_symmetry_resid the tautological assembled-matrix one. port_coupling is Q1/sqrt(1 + Q1^2) with Q1 = coupling_Q1, not 1.

    noise_curve ¶

    noise_curve(
    omega0: float | None = None,
    *,
    half_widths: float = 60.0,
    decades: float = 3.0,
    points_per_decade: float = 48.0,
    extra_omega: Sequence[float] | None = None,
    omega: Sequence[float] | None = None,

    The exact N_V(omega) of this setting tabulated for the finite-band kernel.

    The finite-band kernel needs N_V(omega) of each setting (one tuning capacitance, one coupling), not the single-pole reduction of it; this returns it on a grid that the C++ kernel_row_noise interpolates log-log. The grid is symmetric in the detuning,

    ``omega = omega0`` and ``omega0 +- hw x``,  ``x`` geometric over
``[10^-decades, half_widths]`` at ``points_per_decade`` points per decade,

    with hw half the noise-doubling width of the equivalent pole, so it resolves the resonance (where N_V is flat, so the x < 10^-decades gap costs nothing) and the |Z|^2 ~ (2 L domega)^2 wings (where N_V is a power law, hence exact in log-log). half_widths = 60 covers the window the discrete sums use (+-40 half-widths truncate below 1e-5). The interpolation error of N_V is second order in the step, ~(ln 10/ppd)^2/8, so 48 points per decade keeps K (which goes as 1/N_V^2) accurate to a few times 10^-4; halve points_per_decade to check.

    extra_omega merges extra frequencies into the grid. Use it for structure that does not scale with the detuning -- above all a self-resonance of Z_p (a pole at a fixed frequency), which a grid centred on omega_0 resolves only by accident.

    Pass omega= to use your own grid instead. Returns omega_rad_s, f_Hz, N_V_V2_s and its components (thermal, backaction, imprecision, correlation), plus omega0_rad_s, f0_Hz and N_V_at_omega0_V2_s.

    Receiver(
    T_cav_K: float = 0.0,
    N_A: float | None = None,
    T_A_K: float | None = None,

    Noise model of a single-port haloscope receiver.

    Exactly one way of fixing the noise level:

    • T_sys_K: a total system noise temperature as quoted by the experiment, referred to the cavity port (flat in detuning; k_B T_sys per Hz). Overrides the physical noise model; only eta_snr still applies (eta_out must stay 1).

    • otherwise the physical model, in quanta per Hz referred to the amplifier input:

      N_sys(delta) = k [ eta_out N_port(delta) + (1 - eta_out)(n_in + 1/2) + N_A ], N_port = |chi|^2 S_cav (n_in + 1/2) + (1 - |chi|^2)(n_c + 1/2),

    |chi|^2 = ((beta - 1)^2 + x^2)/((beta + 1)^2 + x^2) the cavity reflection, x = 2 Q0 delta/f, n_c the cavity-bath occupation (n_cav if given, else n_th(T_cav_K)), n_in = n_th(T_in_K) the occupation of the termination incident on the port AND of the transmission-loss baths (all at the fridge temperature; T_in_K defaults to T_cav_K), S_cav the squeezing delivered to the cavity (1 without squeezing), k = 2 for a phase-sensitive readout, else 1. This is 2301.09721 Eq. A4 (with alpha = eta_out, rho = squeeze_eff, G_S = 1/G_s). With an isolator at the cavity temperature and no squeezing, N_sys = k(n_c + 1/2 + N_A) is flat and independent of beta. T_in_K = 0 mimics "no isolator, cold amplifier input" (Kim et al. 2020 Sec. 3).

    eta_out (HAYSTAC's alpha, 2301.09721 Table II): power transmission between the cavity port and the amplifier. It attenuates the axion signal (scan_rate and the limits multiply P by it) and replaces a fraction 1 - eta_out of the cavity output by fresh noise at n_in. N_A is then the added noise referred to the AMPLIFIER input (HAYSTAC's N_a).

    N_A (quanta, excludes the input 1/2: SQL = 0.5) or T_A_K (classical HEMT noise temperature, N_A = k T_A/hf).

    phase_sensitive=True (HAYSTAC phase II squeezed-state receiver, SSR): one quadrature is measured; the axion's random-phase signal puts half its power there, so the noise is reported in phase-insensitive-equivalent quanta N_sys = 2 N_quad, with N_quad counted so that vacuum is 1/2 (the convention of the corrected HAYSTAC analysis, arXiv:2301.09721 Sec. III, Eqs. A1, A3-A6). An ideal phase-sensitive amplifier without squeezing therefore gives N_sys = 1, the same as the SQL phase-insensitive one (no free lunch). N_A is then the single-quadrature added noise (HAYSTAC's N_a).

    Squeezing convention (Malnou et al. 2019, arXiv:1809.06470): squeeze_dB is the squeezer's own one-quadrature gain G_s = 10^(dB/10) (noise reduction at the squeezer OUTPUT, before any loss). squeeze_eff is the squeezer -> cavity transmission eta_1 (HAYSTAC's rho = (alpha rho)/alpha), so S_cav = eta_1/G_s + 1 - eta_1 (2301.09721 Eq. 6 at the cavity). A squeezing MEASURED at the receiver output already contains N_A and eta_out; never enter it as squeeze_dB -- convert it with squeezer_gain_dB(), which removes N_A (otherwise the added noise is counted twice). The squeezer and the measured quadrature are centred on the cavity frequency, so chi(delta) multiplies both sideband quadratures by the same factor (chi(-delta)* = chi(delta)): no rotation of the ellipse, anti-squeezing never enters. This agrees with Malnou et al. Eq. 2. eta_snr multiplies the SNR (analysis efficiency, < 1), so the rate goes as eta_snr^2.

    Attributes: stat_error (None when there is none), error (the estimator: "sem", "clopper_pearson", "poisson", "batch_means" or "upper_limit"), events (events of the sample), events_defined (events where the variable is defined and the selection holds), units, mc (always True), upper_limit and cl (after zero events), interval (a fraction's Clopper-Pearson interval) and reason (why there is no error).     derive_seed ¶

    derive_seed(seed: int, *keys) -> int

    z = seed mod 2^64, then for each key z = mix(((z XOR h(key)) + 0x9E3779B97F4A7C15) mod 2^64), with mix SplitMix64's output function, h(int) = the int mod 2^64 and h(str) the first 8 bytes (little-endian) of the SHA-256 of its UTF-8. Injective in the last key for fixed earlier keys.
